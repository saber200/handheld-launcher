## 给 coding agent 的开场指令（可直接复制）

```
读取 FantasyHub-改造实现规格书.md，对现有 handheld-launcher（FantasyHub）做界面与交互改造。

硬性约束：
1. §0「不许丢的东西」里的 10 项能力一个都不能删或简化；任何一项做不到就停下来问。
2. 保留现有 useGamepadNav 的焦点域机制（data-focus-zone + [data-focusable] + LT/RT），
   只换视觉规范，不要重写导航内核。
3. 先做 M0：把 reference/design-tokens.json 转成 src/styles/tokens.css，
   再用侧栏替换顶部标签条 + 实现锁定态。在此之前不要动页面内容。
4. 圆角禁胶囊与椭圆：全仓不得出现 border-radius: 999px 或 h/2 形式的全圆角。
   只有状态圆点（≤9dp）与手柄按键角标（26dp）是正圆。
5. 间距走 §2.2 的令牌，不写手感数字：卡片内边距 16、同组 8、不同组 ≥16、文字距容器边缘 ≥3。
6. 本机（macOS）编不了 Windows 分支 —— 不要声称已验证；Windows 侧靠 CI 的
   build-windows.yml 与 gamebar.yml。
7. 每完成一个里程碑，跑 tools/ 下三个脚本，全绿再进下一阶段。
```

## 三个最容易做错的地方

1. **游戏库的横向卡片条要整体重新居中**。聚焦项放大 1.36× 后必须仍居中于内容区（`contentX=260, contentW=996`），左右邻卡部分露出。算法在规格书 §3.3，直接抄。
2. **软件库卡片的四段结构**：包头行（状态/角标）→ 图标区 → 名称 → 底部操作。包头行**必须落在卡片背景上**，不能放进图标区（放进图标区会与圆角错位，上一版就是这么错的）。
3. **锁定态不参与焦点循环**。商店/社区要同时满足：不可进入 `[data-focusable]`、LB/RB 跳过、读屏播报「不可用」、不弹任何提示框。

| --- | --- | --- |
| 一级导航 | 顶部 4 标签（胶囊）水平居中 | **左侧 236dp 竖排侧栏**，8 项（含 2 个锁定） |
